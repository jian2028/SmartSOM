## 直接打开

在当前仓库根目录执行；关闭窗口后命令返回。两条命令可在两个 Terminal
标签页分别执行，以便对照同一个 tick。

```sh
python scripts/validation/historical_replay.py play rule
python scripts/validation/historical_replay.py play marl
```

这是冻结的历史播放器。Play/Pause 控制播放，Step 前进一步，拖动时间轴
可前后跳转。开头地图 Input 的 `×10` 表示十个在厂 job，右侧表格逐个列出；
底部 `Outside queue: 10` 是另外十单，初始一共二十单。
底部 `Good delivered` 才是合格交付量；`Exit attempts` 包含质量失败，
不能当作成功交付。质量失败会产生重试。

## 原始场景

- 原始对称 Template 1 布局：四台机器、四辆 AGV；读取原运行保存的工厂文件。
- 5,000 ticks，初始二十单，Input 容量十；每 tick 到达概率 0.1。
- 路线长度在 2、3、4 中取值，加工需求在 12、18、24 中取值。
- 三种加工模式时长倍率为 1.25、1、0.8，不良概率为 0.05、0.1、0.15。
- 紧急单概率 0.05，普通/紧急交期系数分别为 2.5/1.5；电池行为关闭。
- 两者使用相同世界种子；MARL 保留原来的随机采样推理，无规则接管。

## 发生了什么

| tick | Rule 合格交付 | MARL 合格交付 | MARL 累计冲突 |
| --- | ---: | ---: | ---: |
| 1,000 | 32 | 19 | 240 |
| 2,000 | 65 | 46 | 440 |
| 3,000 | 108 | 74 | 717 |
| 4,000 | 139 | 99 | 949 |
| 5,000 | 167 | 121 | 1,140 |

两者累计到达均为 528 单。规则在 5,000 ticks 完成 818 道工序，MARL 为
667 道；机器利用率分别为 63.68% 和 51.805%。规则检测 158 件，MARL
检测 2 件；输出质量失败分别为 62 次和 76 次。规则冲突计数为零。
这些是观察到的行为差异，不能单独证明某项差异导致全部产量差距。
冲突是原运行时阻止执行的冲突动作计数，不表示车辆真的重叠碰撞。

终态守恒：规则 `528 = 167 交付 + 25 在厂 + 336 厂外`；MARL
`528 = 121 交付 + 22 在厂 + 385 厂外`。这是固定时长的持续到达场景，
不以完成所有到达订单为停止条件。
