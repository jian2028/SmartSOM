# 0041 — Registered public observation fields

Date: 2026-10-12
Status: Local development preparation; integration and independent review pending

Extends ADR0036's explicit full policy selectors. The V3 physical transition,
decision identities and historical encoders remain unchanged. This is not a new
simulation version. It does not supersede historical evidence or authorize an
experiment launch.

`builtin.public_fields@1` and `builtin.scoped_candidate@1` form an explicit pair.
An ordered YAML list selects registered Python components, declared normalization,
supported resource aggregation and actor/critic visibility. No expressions,
executable import paths, evaluation or general computation language are accepted.
New calculations require a named Python implementation in both registries, a
schema/version decision and focused tests. Immutable source hashes pin the pair;
configuration, ordered layout, dimensions and package state are checked on read.

Old selectors continue through byte-unchanged policy-contract and policy-factory
modules. Their implementation digest stays unchanged. No default opt-in, index
remapping, reinterpretation or repair of historical checkpoints is performed.
Full continuation retains the application's existing implementation-identity
check; cross-source resume is not implied by inference compatibility.

Registered components receive a detached restricted request. It includes released
routes, public quality/risk, current physical resources, own semantic target,
legal candidates and conditional selection prefix. It excludes announced future
orders, metrics, returns, latent defects, realized duration, dead reservation
fields and other agents' semantic targets. Intention counts are removed from
both source context and Dispatcher candidates. Available supply retains its
existing boundary-cache timing, and actual available/locked jobs remain public.
Old arbitrary observation plugins keep their historical wider input; this
restriction does not establish the same guarantee for that compatibility path.

Presence plus PASS distinguishes absent, UNKNOWN and PASS job/cargo summaries.
Every inspection station must have automatic disposal for this encoding. Public
FAIL outside DISPOSING and any actionable FAIL/DISPOSING fail closed. DISPOSING
still occupies its physical slot but contributes neither prospective operation
counts nor available work/urgency. End sinks contribute no accumulated job counts.

Finite inventory/supply counts divide by their actual resource capacity.
Unlimited owners use the declared projection count scale and carry an explicit
unlimited flag. Exact public nominal times use declared rational work, machine
overrides, rate, selected/reference mode and the physical rounding contract.
They never consult disturbance samples. Empty-machine nominal/elapsed fields
are zero. Eight aggregate work fields remain critic-only.

Context has two equal-width planes; scoring uses only the actor plane and value
uses only the critic plane. Conditional candidate and prefix components remain
actor-only, including DQN Q scores. No critic pool/prefix aggregation is added.
This representation reuses existing ragged packet, learner and batch paths.

The user selected removal of other AGVs' has-target bits and all attempt inputs
from this encoding. Own target and other AGVs' real position, cargo and service
remain. Attempts stay in core counters and recorded diagnostic state. Disposal
and replacement retain the original demand's release and due times. Additional
AGV/spatial redundancy decisions remain separate; no further fields are removed.
This development slice supplies no final Batch05 data matrix and no new Mover
algorithm. The separately authorized local-map repair gates that component to
Dispatcher/Mover, centered on the actual owner AGV. Machine/Buffer receive a
zero placeholder with applicability zero, preserving a common declared width.
YAML can further restrict component roles with `applies_to`; layouts and package
identity freeze this selection. Dispatcher semantic targets and the existing
Mover execution contract remain stable. Matrix transport allows abstract road
overlap and resolves port service competition; its physical position features
must not be described as grid collision/congestion signals. Learning a future
physical Mover requires explicit grid transport and a separate algorithm change.
Reward shaping and task-state visibility remain different axes.
