# 科研软件与重构验证

只选择本次改动相关条目。建立可验证的契约，不把旧实现的一切行为或论文中的候选设计当成事实标准。

## 模型与算法

- 公式、单位、时间尺度、舍入、边界、终止条件、约束与状态转移是否符合已确认需求？是否混淆实现便利与建模假设？
- 检查状态/资源守恒、唯一所有权、原子更新和事件顺序；使用可手算的小例，必要时用独立参考实现或公认基准。
- 学习/决策代码检查可用信息边界、未来信息泄漏、训练/评估分离、动作合法性、奖励与目标、终止/截断处理；按具体算法适用，不预设固定设计。

## 随机性、数据与指标

- 源码版本、输入、依赖、关键环境和随机源是否可追踪？复现要求是逐位、数值容差还是统计一致，必须明确；随机种子相同不保证所有平台逐位相等。
- 对照是否共享应固定的条件、数据划分和预算？随机源耦合、采样方式、模型选择和预处理是否改变对照含义？
- 指标分子/分母、聚合单位、失败样本、缺失数据和过滤条件是否正确？是否把未完成样本排除后制造改善？
- 只有改动涉及实证效果或提出研究结论时，要求相应重复、误差/不确定性和实验设计依据。日常 bugfix 不自动启动昂贵多种子训练。

## 独立测试与重构

- 测试预期来自规格、数学关系、手算或独立参照；调用被测函数生成 expected 会形成自证。
- 性质/变形测试要有成立前提，例如只有当标签不参与策略和随机映射时才可要求重命名不变；不能把未经证明的“直觉性质”写成规范。
- 重构先列出行为保持项和批准变更项。保持项做差分/回归，变更项按新契约验收；不能要求修复后的行为复制旧 bug，也不能以“重构”为由跳过回归。
- 涉及配置、数据格式或 checkpoint 时检查真实兼容需求、迁移和错误提示；只有确有需求才增加兼容层。
- 性能或结构改动验证语义保持；浮点、并发和随机实现变化采用明确容差或统计准则，解释无法严格等价的部分。

## 证据边界

分别记录代码审查、实际执行、工程验收、科研效果和独立复现。测试全绿不证明模型准确、研究假设成立或方法优于基线。审查没有发现问题也不证明没有问题。
